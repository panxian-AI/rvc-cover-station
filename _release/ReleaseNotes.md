# RVC 翻唱站 v2.4.0 · 三家音源全部支持扫码登录

> **症状**：网易云能在控制台扫码登录，QQ 音乐和酷狗只能自己去浏览器 F12 里翻 Cookie——
> 粘错一个字符就「取不到直链」，还看不出来是粘错还是号过期。手机上有 App，
> 电脑上却没个能扫的东西。
>
> 这一版把扫码补齐：**网易云 / QQ 音乐 / 酷狗三家都能扫码**，二维码画在控制台弹出层里，
> 手机 App 扫一下确认就生效。扫进来的 Cookie 和粘贴一样进账号池，扫第二个号就多一个账号。

---

## 一、为什么以前只有网易云能扫

扫码这事每家平台的流程完全不同，网易云那套（`unikey` + `client/login` 轮询 801/802/803）
是早前就摸清写进 `ncm_login.py` 的；另外两家一直没做，因为它们不是「一个接口拿 key、
一个接口轮询」这么简单：

- **QQ 音乐**：登录走 QQ 互联的网页扫码，扫码只是第一步；确认后还要跟着 `check_sig`
  拿到 `p_skey`，再用它算 `g_tk` 去调 `oauth2.0/authorize` 换 `code`，最后拿 `code`
  调 `musicu.fcg` 的 `QQConnectLogin.LoginServer` 才换出 `qm_keyst`——少一步都只有
  「登录成功」但取不了流。
- **酷狗**：接口要 web 签名（参数排序后前后各拼一次固定盐再 md5），二维码是上游直接画好的
  PNG，而且状态码是 0/1/2/4 而不是网易云那套。

所以「顺手加个扫码」在这两家是三条不同的链路，不是给网易云那套换个 URL。

## 二、这一版怎么改的

**1. 每家适配器自带一个 `QrLogin`**

```
ncmapi/sources/netease.py   QrLogin：unikey → 轮询 801/802/803
ncmapi/sources/qq.py        QrLogin：ptqrshow(qrsig) → ptqrlogin → check_sig(p_skey)
                                    → oauth2.0/authorize(code) → musicu.fcg(qm_keyst)
ncmapi/sources/kugou.py     QrLogin：v2/qrcode(key+官方二维码图) → v2/get_userinfo_qrcode
```

对外统一两个方法：`start() -> {"key", "qr"/"img"}`、`poll() -> (state, cookie)`，
state 一律换成网易云那套 **801 等待 / 802 已扫 / 803 成功 / 800 过期**——
前端一份轮询逻辑通吃三家。

**2. 二维码两种来源，都不用装第三方库**

- 网易云：拿到 `codekey` 后由 `ncmapi/_qr.py`（纯标准库编码器）现画成 SVG 内联；
- QQ / 酷狗：上游直接返回 PNG，转成 `data:image/png;base64` 内联（439 字节 / 十几 KB，
  比自己在本地画更保真——尤其 QQ 的二维码内容我们没法自己编）。

**3. 面板侧一个弹层管三家**

概览页每家两个按钮：「📱 扫码登录」（有账号时是「📱 再扫一个号」）和「粘贴 Cookie」。
弹层会写清「用哪个 App 的扫一扫」（网易云音乐 App / 手机 QQ / 酷狗音乐 App），
失手时给的是具体原因而不是「失败」：

- 二维码 5 分钟没用 → 「二维码过期了，点「换一张」」
- 扫了没确认（酷狗有这个中间态）→ 「已扫码，请在手机上点「确认登录」」
- 过了所有关但没拿到 Cookie → 「登录成功但没拿到 Cookie（可能没跟到跳转），请改用粘贴方式」
- 网络抖动 → 继续轮询，不把二维码丢掉

**4. 扫码 = 往账号池里加一个号**

扫完的 Cookie 走 `CookieBook.save()`，和粘贴是同一条路：
网易云按 `MUSIC_U` 前 6 位、QQ/酷狗按 `uin` / `userid` 生成账号名，同一个号重扫会覆盖那一个，
不同号就并存。**扫码不再只替换「默认账号」那个老文件**——老文件原样保留，想退出哪个就在
账号行点「退出」。

**5. 会话只在面板进程内存里，5 分钟自动回收**

扫码会话（cookie jar、qrsig、unikey）存在 `ncmapi/sources/__init__.py` 的进程内表里，
前端只拿到一个随机 token，不碰平台密钥；过期会话无论多少都回收，另有 40 个的上限。
`803` 那一刻才落盘，重复轮询同一个 token 不会写第二遍。

**6. 旧入口全部保留**

- `/api/ncm/login/*`（v2.1.5 的网易云专属路由）还在，独立窗口 `设置网易云Cookie.bat`
  和老插件照旧能用；
- 粘贴 Cookie 这条备选路一家没少，扫码被风控拦时照样能过。

## 三、这一版实测与踩到的坑

- **QQ 的 `u1` 只能是 `graph.qq.com/oauth2.0/login_jump`**：换成 `y.qq.com/...` 直接 403
  （`appid=716027609` 是互联快捷登录，回跳地址有白名单），一开始按「回跳音乐站」写就全 403。
- **`ptuiCB('66',...)` 的解析不能贪心**：`ptuiCB\('(\d+)'[^']*',[\s]*'([^']*)'` 会在
  `'66','0'` 这种紧凑格式上匹配失败（`[^']*` 吃掉逗号后还要求再来一个逗号），改成
  `ptuiCB\('(\d+)','[^']*','([^']*)'` 才对。
- **酷狗 URL 里的 `%` 会撞上 `%` 格式化**：`u1=https%3A%2F%2F...` 的 `%3A` 会被当成格式符，
  整条 URL 都坏掉；模板改用 `.format()` 才稳。
- **测试自污染**：`CookieBook` 的 `dir` 在构造时就固定了，测试只改 `base.COOKIE_DIR`
  拦不住已有的 `STORE` 实例——扫码落盘会写进仓库的 `cookies/` 目录，再污染下一个用例的
  取流断言（报「试过 2 个账号」）。修法：测试里连 `STORE` 一起换成指向临时目录的新实例。
- **未知平台不能静默回退网易云**：`normalize()` 的老行为是「不认识就按网易云」，
  扫码时那等于拿网易云的二维码冒充用户要的平台——`qr_start()` 现在先校验平台名再往下走。

## 四、老用户怎么办

- **不用重装**，控制台「版本」卡片点「检查更新」→「立即更新」即可；
  也可以下载 `RVC-Cover-Station-Installer-v2.4.0.zip` 覆盖安装
  （不会动你的成品、声线、访客库、以及 `ncmapi\cookies\` 里已经配好的 Cookie）。
- **面板进程要重启**：新弹层、新路由都在面板里 —— 双击根目录 `停止RVC.bat`，
  再双击 `启动RVC.bat`，刷新浏览器。
- **3002 不用重启**：这一版只加了「怎么拿到 Cookie」，取流逻辑没动；
  扫完的 Cookie 按目录变化自动热加载。
- 已经配好的 Cookie 全部照旧可用，不用重扫；想加号就点「📱 再扫一个号」。
- 不扫码也能用：粘贴 Cookie 的入口一家没少。

## 五、更新方式

控制台「版本」卡片点「检查更新」→「立即更新」，或在 Release 页面下载
`RVC-Cover-Station-Installer-v2.4.0.zip` 覆盖安装。

更新完同样要重开一次 `启动RVC.bat`——更新逻辑在 `updater.py` 里，
Python 只在启动时加载模块。
