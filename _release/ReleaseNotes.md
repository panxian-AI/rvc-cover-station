# RVC 翻唱站 v2.1.0 · 稳定版 · 全面加固

这一版不加新功能，把整个项目从头到尾体检了一遍：逐文件审代码、逐条实测复现、再改再验。
一共修掉 **6 个会丢数据或让公网访客拿到本机权限的严重问题**，以及二十多个「不报错、
但用着不对劲」的毛病。测试从 18 套 939 项扩到 **19 套 966 项**，全绿。

**所有已经装了 2.0.x 的机器都建议更新。** 更新方式见文末。

---

## 一、公网访客可以把「假请求」藏进请求体，冒充本机（安全，最严重）

**症状**：没有任何异常。隧道开着的时候，外面的人如果能构造一条特定请求，就能以
「本机站长」的身份调用 `/api/update/apply`、`/api/data/*` 这些只该本机可用的接口。

**真因**：面板用 HTTP/1.1 长连接，但只在「需要读参数」的分支里读请求体。一条
`GET /login` 带 `Content-Length` 的请求被拒绝/重定向后，body 还留在连接里；下一次
解析请求行时读到的正是这些残留字节——里面可以预先写好一条完整的
`POST /api/update/apply`，而且**不带任何转发头**，`_is_local()` 于是判它是本机直连。

**改法**：每条请求（无论 GET/POST、无论是否 403）进路由之前先把 body 完整读掉，
只读一次并缓存；顺手支持 `Transfer-Encoding: chunked`（以前这种请求体会被静默当成空
对象，`confirm` 缺失还会让人以为「提交成功但没生效」）。超限请求体读完就断开连接，
不让残留字节进入下一次解析。

**回归**：`e2e_security` 新增原始 socket 用例——把一条伪请求塞进 body，断言整条连接
只返回一个响应。

## 二、访客库读不动时会被当成空库，下一次写盘就把真实数据覆盖掉

**症状**：某天打开控制台，访客、申请、白名单全空了；`guest_db.json` 只剩一个空壳。
没有任何报错，备份列表里可能还有旧备份，但最近的记录没了。

**真因**：`guest._load()` 用一个 `except Exception` 把所有读取失败都当成「文件不存在」，
内存换成空库。而访客打开首页就会 `touch()` → `_save()`，把这份空库原子写回文件。
触发条件很日常：用记事本另存成「UTF-8 带 BOM」、手改 JSON 漏个逗号、杀软/同步盘
短暂独占文件。

**改法**：

- 读文件允许 BOM（`utf-8-sig`），能读的就不再误判；
- 真读不动时先复制一份 `guest_db.json.bad-时间戳`，**再**按空库运行，并把原因写进
  `/api/status` 的 `save_error`（概览页红字可见）——原件永远留着，能手工救回来；
- `_shape()` 逐条过滤坏记录（字符串、缺 id、count 写成 null），`touch()`/`visits()`
  的数值转换全部走容错取值。以前一条手改坏的记录就能让**每个访客**的首页 500，
  而且不会自愈。

## 三、删一个声线，会顺手删掉别人的 faiss 索引

**症状**：删掉 `1.pth`、`ai.pth` 这类短名模型后，另一个模型突然「音色变差」——
配套索引没了。索引只能重训，等于毁数据。

**真因**：`models_mgr._match_indices()` 用裸子串判断「这个索引是不是它的」：
`base in 索引名`。`1.pth` 会命中几乎所有 `added_IVF..._1_xxx_v2.index`。

**改法**：只认「名字完全相等」或「模型名 + 分隔符」开头/结尾；模型名短于 4 个字符时
完全禁用模糊匹配。

## 四、重跑安装器：pip 失败会「假成功」，想靠它升级一个字节都不下载

**症状**：装到一半 pip 断了，按提示重跑安装器 → 秒完、提示安装成功，可面板一启动就
报缺包。或者：已经装过旧版，重跑安装器想升级 → 提示成功，版本号却没变。

**真因**：安装器开头判断「两个 venv 都存在就跳到只补模型」。venv 是在 pip **之前**
就建好的，所以 pip 失败后重跑必然命中这个分支；而「只补模型」也跳过了下载源码那段。

**改法**：去掉这个隐式跳过（只保留显式 `RVC_ONLY_MODELS=1` 的「只补模型」入口），
重跑安装器现在会重新下载并覆盖代码、pip 也会把缺的包补上。同时：

- `move` 改成 `robocopy /E` 合并覆盖。cmd 的 `move` 在目标目录已存在时会把源目录
  **塞进去**（`RVC-WebUI\RVC-WebUI`），外层旧 `webui.py` 还在，校验照样通过——用户
  以为装了新版，跑的还是旧代码；
- `curl` 加 `--fail`：404 错误页不再被当成 zip 下载成功，文档承诺的「锁版本失败自动
  回落 main」才真的会走；
- 安装器会把自己复制进安装目录（所有排障提示都让用户去那里双击它）；
- Python 安装器返回 3010（成功但需重启）不再被判失败、白下三次；
- 模型下载脚本失败会返回非零退出码，安装器据此提示「模型不齐」——以前永远返回 0。

## 五、卸载时选「保留个人数据」，访客库照样被删

**症状**：卸载时按 Y 保留数据，备份文件夹里只有成品 mp3，`guest_db.json` 不见了。

**真因**：备份路径写的是 `RVCSVC\guest_db.json`，真实位置是
`RVCSVC\dashboard\guest_db.json`；`move` 失败又被 `>nul 2>&1` 吞掉，紧接着整个安装
目录 `rd /s /q`。

**改法**：路径改对，并同时备份高级设置、公网开关、成品索引；「已备份」的提示也按
访客库是否存在来判断。

## 六、成品库索引：并发归档丢记录，读失败就把整份索引清空

**症状**：同时做 2 单以上时，偶尔有一条成品在列表里「没名字」或干脆消失（mp3 还在）；
极端情况下所有成品的歌名/声线/升降调一起丢。

**真因**：`_load_index()` 与 `_save_index()` 各拿一次锁，「读 → append → 写」之间
的空档足以让另一单插进来，后写的用旧快照盖掉先写的。读失败时 `except: return []`，
调用方 append 一条再写回，就把「读失败」固化成了「索引真的空了」。

**改法**：新增 `_mutate_index()`，读改写在同一把锁里；索引损坏时先另存
`covers/index.json.bad-时间戳`，并把原因暴露出来。成品文件名改用
`O_CREAT|O_EXCL` 原子抢名——以前「exists 再 copy2」在并发同名时会互相覆盖，
两条索引指向同一个文件（下载到别人的声音）。TTS 与翻唱共用这一套。

## 七、导入备份：把正在跑的单打回队列，还会把 done 降级成 error

**症状**：制作中导入一份备份（含自己刚导出的那份）后，同一单出现两个进度、TTS 真的
合成两遍；或者明明已经做完的单变成「失败」，成品链接打不开。

**真因**：

- `_normalize()` 无条件把 `running` 改成 `queued`（它假设备份来自别的机器），本机
  正在跑的 job 也被改，`pump()` 于是再开一单；
- 合并模式按「谁的时间新」整条覆盖，包里较新的 `error` 会把本机 `done` 连同 `file`
  一起盖掉。

**改法**：`running` 只在「本机确实没有这个 job」时才回队列（查不动就保留，宁可多等
一轮）；合并时 `done` 永不被非 `done` 覆盖。另外：

- 回滚基线改用 `guest.snapshot()`（内存），不再读可能滞后的文件；
- 音频只解压「预检已校验 sha256/大小」的清单条目——以前遍历 zip 全部成员，包里多塞
  一个同名 mp3 就能覆盖本机成品，而预检还说「备份有效」；
- 加解压体积上限（单成员 1GB / 整包 6GB），预检阶段就拒收解压炸弹。

## 八、一键更新：写一半失败会把代码目录留在半新半旧

**症状**：更新到一半磁盘满/被杀软占用，面板再也起不来，只能手工从 `_update_backup` 恢复。

**真因**：`open(dest, "wb")` 先把原文件截断再写；失败不回滚；连点两次「更新」还会
两路同时写同一批文件。

**改法**：每个文件先写 `*.rvcnew` 再 `os.replace` 原子替换；失败时按备份整体回滚并
在消息里说明还原了几个；整个 `apply()` 加进程内锁。版本号比较也修了：以前只取前三段，
发 `2.0.1.5` 时老机器永远收不到提示。

## 九、其余「不报错但不对劲」的修复

- **验证码第 13 次以后不再锁定**：阶梯用 `== 6/9/12` 判断，streak 涨到 13 就再也
  命中不了。改成 `>=` 并记住已用到第几档。
- **设置页每 15 秒重绘高级设置**：改到一半停手超过 15 秒，输入被服务端旧值覆盖。
  现在只要动过或焦点还在表单里就不重绘。
- **「一键退出」失败后按钮永久变灰**：后端明确提示「可以再点一次」，前端却没恢复
  按钮。现在失败就恢复。
- **翻唱页轮询失败静默卡死**：`/api/cover/job` 一报错就 `clearInterval` 走人，进度条
  一直转、按钮永久灰。现在重试 5 次后给明确提示并恢复按钮。
- **模型名带撇号，删除按钮点了没反应**：`encodeURIComponent` 不编码 `'`，把 onclick
  里的 JS 字符串提前截断。成品名、访客 IP 同类问题一并改成专用 `jsq()` 转义。
- **启动器把「端口能连上」当面板已就绪**：别的程序占着 8899 时不开面板也不报错，
  浏览器打开一个不是面板的地址。现在探测 `/api/ping` 的 `app` 标识。
- **托盘图标没放上却报「已就绪」**：只看了窗口句柄，没看 `Shell_NotifyIcon` 的失败。
- **重复点「启动服务」会起第二套后端**：现在按端口判在跑就拒绝；顺手补了日志句柄
  泄漏与 `pid_alive` 的 ctypes 原型（64 位下句柄会被截断）。
- **清空市场缓存可以误删整块盘**：`RVC_MARKET_CACHE` 指向 `E:\` 时照样 `rmtree`。
  现在复用「盘根/系统目录/用户主目录一律不动」的闸门。
- **安全日志过 512KB 后不再记录**：文本流不支持负数 seek，异常又被吞掉，轮转和追加
  一起失效。改成二进制截断，失败也照样追加。
- **公网访客的 favicon 每次 403 并写一条安全日志**：白名单里有这个路径，但处理它的
  分支在「只认本机」之后。现在公开返回 204，安全日志不再被噪声淹没。
- **静态资源可以借盘符逃出 assets 目录**：`/assets/C:/x.js` 会让 `os.path.join` 丢掉
  前半段。现在拒收 `:` 并做 realpath 归属校验。
- **TTS 同一段文字连点两次会真合成两遍**：翻唱有 `_inflight` 去重，TTS 没有。
- **老版 torch 保存的 `.pth` 被误判成「不是权重」**：只认 zip 头，现在也接受
  `\x80\x02` 的 pickle 流。
- **默认成品目录的路径/端口来源不一致**：`tunnel.py` 不认 `RVC_CLOUDFLARED` /
  `RVC_PANEL_PORT`，会出现「面板说找到了、隧道说没有」或指向没人监听的端口。

## 老用户怎么更新

两种都行，**推荐第一种**：

1. **控制台「概览 → 检查更新 → 立即更新」**，完成后关掉面板窗口，重新双击
   `启动RVC.bat`。
2. 下载本页的安装包，解压后双击 `一键安装.bat`（现在重跑安装器会真的覆盖代码，
   已有的模型和 .venv 不会重下）。

> ⚠️ 更新完必须重启面板。`panelkit/` 是运行中加载的，旧进程不会自己换代码，
> 看到的还是旧页面。

## 这次没做的

- 在线更新仍然只做 zip 自洽校验（CRC），没有签名校验；线路里有第三方加速镜像。
  在意供应链风险的话，请用 GitHub 官方地址直连。
- 后端推理调用没有整体超时（`gradio_client` 本身不提供）。后端假死时该单会一直占着
  并发槽位，需要重启后端。下一版考虑加看门狗。
- `guest.py`（1800 行）、`dataio.py`（1150 行）、`market.py`（1100 行）仍是单体，
  计划在下一版按业务拆成多个模块。
