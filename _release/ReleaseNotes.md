# RVC 翻唱站 v1.4.2 · 排队位次与制作进度看得见

小更新，只改「看得见」这部分，不动推理链路。

## 一、访客页：知道自己排第几、还要多久

**症状**：访客提交之后卡片上只有「排队中」三个字。排第几不知道，前面还有几个人
不知道，是不是卡住了也不知道；轮到「制作中」更没下文，只能一直刷新碰运气。
被问得最多的两句就是「我排到哪了」「还要等多久」。

**真因**：位次其实已经算出来了（`q_pos`），但只显示成 `排队中 #2`，没有总数、
没有前面还有几单、没有时间；而「制作中」这一档，服务端压根没把阶段存下来——
`_watch` 只在完成/失败时回写状态，中途每次轮询拿到的 `stage` 用完就丢了，
所以前端想显示也无从显示。

**改法**：

1. `_watch` 每 3 秒把任务当前阶段抄回申请记录（**只改内存不落盘**，阶段本来就是
   瞬时状态，没必要每 3 秒写一遍 JSON）；
2. 单子开始制作时记下 `started` 时间戳（和 `decided` 分开：一个是「开始做」，
   一个是「本轮结束」，含义不同，老记录没有它就按 0 处理，不显示耗时）；
3. `/api/guest/my` 与 `/api/admin/queue` 统一多给一组字段：
   `q_ahead`（前面几单）、`eta_sec` / `eta_text`（预计）、`stage` / `stage_label`
   （阶段）、`elapsed_text`（已用）、`pct` / `left_text`（进度/剩余）。

访客页每单变成：

```
🎤 某首歌                                  [ 排队 · 第 3 位 ]
某歌手 · 某声线 · 11-04 16:57
▬▬▬▬▬▬▬▭▭▭▭▭▭▭▭▭▭▭▭
前面还有 2 单 · 你在第 3 位（共 3 单） · 预计约 2 分 15 秒开始
```

制作中换成绿色的第三步 + 进度条 + 「正在制作 · 下载 / 分离 / 演唱 · 已用 32 秒 ·
预计还剩约 45 秒」。卡片上方还多一行汇总（`🎬 制作中 1 单` / `🎧 排队 2 单 ·
最快一单第 1 位`），不用逐条数。

## 二、总面板：正在做的那单不再只有标题

**症状**：控制台「制作队列」的横条只有「正在做：某首歌」——不知道跑到哪一步、
跑了多久；排队行只有 `#1 #2`，看不出还有多久轮到自己；「申请记录」的状态列
也只有「排队中 / 制作中」四个字。

**改法**：

- 正在做的**每一单独占一行**：阶段 + 已用时间 + 预计剩余 + 进度条（`running_detail`）；
- 排队行加「前面 N 单 · 预计约 X 开始」，第一行写「下一个就做」；
- 顶部横条多一个「单均约 45 秒」，告诉你估算基准是什么；
- 「申请记录」状态列：排队中带位次，制作中带阶段和已用时间；
- 「🎤 自助翻唱任务」卡片同步加进度条（口径一致）。

## 时间是怎么估的（不是随口编的）

- **位次**：队列里的真实下标，精确值，不是估算；
- **平均耗时**：最近 12 单成品的「开始制作 → 出成品」取**中位数**（不用平均数：
  偶尔一单卡死会把均值拉烂），没有历史时退回 45 秒；
- **排队模拟**：先看正在跑的单各自还剩多久（按平均耗时算），空槽位算「现在就空」，
  排在自己前面的人依次占掉最早空出来的那个槽位，自己拿到的时间 + 一单耗时 = 预计；
- **进度条封顶 92%**，到点没做完就停在 92%，快结束时文案改成「快好了」——
  宁可保守，也不演「100% 了却还在等」。

换硬件、改「同时制作数量」、换声线之后，这些数会自己跟着变：全部现算，没有写死。

## 老用户怎么办

不用做任何事，自更新到 v1.4.2 即可。这一版只改了访客页、控制台页面和几个接口
返回的字段（老字段全部保留，`running` / `running_all` 还在，外部脚本不会断）。
访客的 `guest_db.json` 结构不变，只是老记录没有 `started`，那些历史单不会显示
耗时——新单开始就正常了。

**要重启面板**（托盘菜单「停止服务并退出面板」后重新双击 `启动RVC.bat`），
因为 `guest.py` / `cover.py` 是面板进程内的模块，不重启跑的还是旧代码。
