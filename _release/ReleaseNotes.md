# RVC 翻唱站 v1.5.0 · 数据可备份、可迁移

中型更新：新增「数据备份与迁移」。不动推理链路、不动已有数据格式，只是给
`guest_db.json` 这份单点数据补了一条退路。

## 一、为什么现在做这个

**症状**：整站最值钱的东西——几百条访客记录、几十条申请、白名单、成品库索引——
全都躺在 `dashboard/guest_db.json` 一个文件里。想留个后路只有「整目录拷走」：
226MB 成品 + 几个 G 的模型，拷一次半小时，还容易漏掉 `advanced_settings.json`
和 `covers/index.json`；手改 JSON 改坏一个逗号，全站访客页直接白屏，也没有
「回到上一版」的按钮。

**改法**：控制台多一张「数据备份与迁移」卡片。三个动作：导出备份、导入备份、
打开备份文件夹。备份落在 `RVCSVC/_backup`，和代码同盘——升级代码不会冲掉它。

## 二、导出的包里装了什么

| 条目 | 内容 | 默认 |
| --- | --- | --- |
| `data/guest_db.json` | 访客 / 申请 / 队列 / 白名单申请 / 白名单 | 必含 |
| `data/advanced_settings.json` | 同时制作数量、音高算法、混响等全部参数 | 含 |
| `data/covers_index.json` | 成品库索引（歌名、声线、时间、大小） | 含 |
| `covers/*.mp3` | 成品音频本身 | 勾选才带（约 200MB+） |
| `models/manifest.json` | 已装声线清单（名字 / 大小 / 时间） | 含 |
| `manifest.json` | 本包元信息：版本、时间、机器名、各条条数、每个条目的 sha256 | 含 |

**为什么带一份声线清单**：换机器时最容易忘的就是「我这台装过哪几个声线」。
清单里没有权重（那玩意动辄几百 MB），但导入时会拿它和本机比对，缺哪个当场列出来
——照着名字去模型市场补齐就行。

`manifest.json` 是整包的身份证：`app` 必须是 `rvc-cover-station`、`kind` 必须是
`data-backup`、`schema` 不能比本机认得的高。别的程序的包、改过的包、没下完的包，
在预检阶段就会被挡回去，不会碰到你的数据。

## 三、导入分两步，也分两种

**第一步只读**：选完包先给你看一张对照表——

```
项目        本机现在   覆盖导入后   合并导入后
访客          306        306          306
申请           46         46           47
其中待批        0          0            1
白名单          2          2            3
```

同时写清包里有多少成品索引、带不带音频、有没有本机缺的声线。

**第二步才动手**，两种方式：

- **覆盖**：本机数据整份换成包里的（本机独有的记录会消失）。换机器、恢复出厂、
  改坏了回滚——用这个。
- **合并**：两边合起来，按业务主键去重（访客 / 申请用 `id`，白名单用 `gid`），
  同一条取「更晚决定」的那次状态。两台机器各自攒了一批记录，合成一份用这个。
  **同一个包导两次不会翻倍**——这是合并模式和「简单拼接」的分界线。

两种方式都要求先勾「我确认要改写本机数据」，接口层也校验这个字段，脚本直连
不给就是 400。

## 四、折腾坏了也能退回来

- **导入前自动存档**：动手之前先把本机现有数据整份导出一次，名字带「导入前自动备份」，
  在备份列表里标 🕘。导错了直接再导回来。
- **写失败整体回滚**：写库、写设置、写索引任何一步抛异常，自动用刚才那份存档把
  三份文件原样写回，并告诉你回滚结果。成品音频先解到临时目录，全部成功才搬进
  成品库，失败不会留下半截文件。
- **坏包伤不到你**：包里的条目名只认白名单（`data/` 下三个固定文件、
  `models/manifest.json`、`covers/` 下一层 `.mp3`），**从不按包内声明的路径解压**，
  所以 `../../` 那种路径穿越在预检阶段就被拒，写不出成品库以外的地方。
- 备份列表里的「删」只认备份目录下的 `.zip` 基名，传 `../guest_db.json` 会被打回。

## 五、几个替你想到的情况

**备份是「制作中」做的怎么办**：那些 `running` 记录对应的任务进程在目标机器上
根本不存在，原样导进来队列会永远卡在一个跑不完的槽位上。导入时统一改回 `queued`
让它重新排一次，同时清掉指向旧机器的 `job` / `file`，访客还能等到成品。导入完成
会告诉你有几单被这样处理了。

**一次灌进几百条待批会不会把队列撑爆**：会，所以导入时按原有上限裁剪——
访客 400、申请 300、白名单 200 条。待批 / 排队中的优先保（那些是访客还在等的），
终态的按时间留最近的；如果连待批的都超上限，只留最新的那批。

**只导了索引没带音频**：成品库列表里能看到那些歌，点开却提示缺文件。预检会提前
警告，并告诉你「要音频就导出时勾『连成品音频一起打包』」。

**全新机器上导入**：本机没数据时，「导入前自动备份」会返回「没有可导出的数据」——
这不是错误，流程照常往下走，不会因为「没法备份」就不让你恢复。

## 老用户怎么办

自更新到 v1.5.0，然后**重启面板**（托盘菜单「停止服务并退出面板」后重新双击
`启动RVC.bat`）——`dataio.py` 是面板进程内的新模块，不重启就没有这张卡片。

数据格式一个字节没变：`guest_db.json` 结构照旧，`SCHEMA = 1` 就是现在这份格式，
以后真改结构才会升到 2，届时新版能读老包、老版会明确拒绝新包并提示先升级。

**建议现在就去导一份**：点「⬇ 导出备份」，不勾音频只有二十来 KB，几秒钟的事。
