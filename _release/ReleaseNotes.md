# RVC 翻唱站 v2.3.0 · 一个平台存多个账号 + 三家聚合搜索

> **症状**：一家音源只能存一份 Cookie。小号被限流了、会员到期了、收藏在另一个号上——
> 想换号就得把好用的那份覆盖掉，想换回来还得重新粘一遍。搜歌时又得先猜「这首在哪家」，
> 下拉切来切去，切错了搜不到还以为站点坏了。
>
> 这一版把「一个平台一个 Cookie」换成**账号池**：同一家可以存任意多个号，取流时按顺序轮换，
> 面板上每个号单独一行、能单独退出；搜索默认**三家一起查**，结果按平台交错排列。

---

## 一、以前为什么只能存一个账号

`CookieStore` 的设计就是「一个平台 = 一个文件」：

- 网易云 `ncmapi/ncm_cookie.txt`、QQ 音乐 `ncmapi/cookies/qq.txt`、酷狗 `ncmapi/cookies/kugou.txt`；
- 保存 = 整份覆盖；登录态 = 这个文件在不在、能不能查到昵称；
- 取流只用这一份 Cookie，失败就失败。

三个直接后果：

1. 换号必然覆盖，旧号想切回来要重新粘贴；
2. 单号被限流（网易云很常见）没有任何退路，直接「下载失败」；
3. 概览页只有一行「已登录 / 未登录」，看不出有几个号、哪个坏了。

聚合搜索是同一个根：`search(platform)` 一次只查一家，`platform` 留空就落到默认平台，
所以「这首到底在哪家」只能靠人一个个试。

## 二、这一版怎么改的

**1. 每个平台变成一个账号池（`CookieBook`）**

```
ncmapi/cookies/netease/<账号>.txt
ncmapi/cookies/qq/<账号>.txt
ncmapi/cookies/kugou/<账号>.txt
```

- 账号名从 Cookie 里的 `uin` / `userid` 推（`u123456`），推不出就用内容哈希前 10 位；
  名字要当文件名，所以统一过一遍 `safe_id()`（`../../escape` → `escape`，有回归守住）；
- 加号 = 再写一个文件，同名覆盖那一个，不同名就并存，想加几个加几个；
- 老文件（`ncmapi/ncm_cookie.txt`、`ncmapi/cookies/qq.txt` …）**自动当「默认账号」只读兼容**，
  排在池子最前面，删它就是删那个老文件——升级不用迁移、不用重新扫码；
- 目录按 (文件名, mtime) 变化热重载，加号、删号都不用重启 3002。

**2. 取流按顺序轮换（`try_accounts`）**

前一个账号拿不到地址（没版权 / 会员曲 / 被限流 / Cookie 失效）就自动换下一个，
全失败才报错，且报错里逐个写清每个账号为什么不行：

```
试过 3 个账号都没拿到 —— u1001：没返回地址；u1002：会员曲目不提供；u1003：登录已过期
```

一个账号都没有时仍是 `need_login=True`，界面提示去配置，而不是让你以为站点坏了。

**3. 三家聚合搜索（`platform=all`）**

```
/search?keywords=十年&limit=6&platform=all
```

三线程并发查三家，**按平台交错合并**（netease → qq → kugou 一轮一首），limit 按家均分，
不会被某一家塞满屏；某一家超时或报错只少几家的结果，原因带平台名回给界面
（`errors: ["酷狗：超时"]`）。翻唱页、访客页、机器人插件的 `platform=all` 是同一条链路；
显式指定某一家就只搜那一家（哪怕它就是默认平台）——不然「我明明选了酷狗」会变成三家混排。

**4. 面板：每个账号一行，逐个退出**

概览页「音源平台」一栏现在这样：

```
网易云   共 2 个账号 · 1 个可用（取流时按顺序轮换）
  ● Inference_Official   已登录 VIP       [退出]
  ● u188****              Cookie 已过期    [退出]
  [📱 重新扫码]  [粘贴再加一个]
```

- 网易云默认走扫码，点「粘贴再加一个」才是粘贴框（避免一进来就问你要 Cookie）；
- 「退出」只删这一个账号，其余账号和别的平台都不动，并告诉你还剩几个
  （还剩多个会补一句「会自动换下一个」），幂等——重复点不报错；
- 「清空」才是整家清掉，按钮文案也写清了；
- 设置页「⚙️ 高级设置 → 聚合搜索」可以关掉聚合（关掉后默认只搜默认平台）。

**5. 登录态不再糊在一起**

以前验活失败（网络抖动、上游 502）会被当成「已登录」，界面显示可用、点歌却失败。
现在验活失败一律 `login=False` +「没验成功（网络或上游异常）」，**不冒充可用**。
一个平台账号多的时候，面板一次最多真去验 3 个（每个账号都是一次真实请求），
其余显示「已保存（账号多，没逐个验活）」，想全验就点「重新检查」。

**6. 顺带：设置项支持开关类型**

`_coerce` 新增 `bool`，收 `true/false/1/0/yes/no/on/off/""`，乱写回落默认值；
设置页按类型画勾选框，保存时读 `checked`。聚合搜索就是第一个用它的人。

## 三、这一版实测踩到的真问题

- **酷狗付费曲白试三种音质**：`status=2`（付费）以前还会继续试 hq / 320k / 128k，
  三次都是同一个结果。现在 `status=2` 直接换下一个账号，省两次请求。
- **酷狗免费曲先 403 是正常的**：拿聚合结果里第一条（会员曲）当样本会以为接口坏了，
  换真免费曲（`paid=False`）立刻 200 + 真直链。所以结果行现在带 `paid` 标记，
  翻唱页和访客页都会显示 VIP 标签——点歌前就知道这首要会员。
- **验活失败 ≠ 已登录**：如上，断网时会显示「可用」是假象。
- **`platform` 空 vs 显式指定**：「默认平台」和「显式选了默认平台」必须区分，
  否则用户选了网易云却得到三家混排。判定用「raw 参数非空」而不是「等于默认值」。

## 四、老用户怎么办

- **不用重装**，控制台「版本」卡片点「检查更新」→「立即更新」即可；
  也可以下载 `RVC-Cover-Station-Installer-v2.3.0.zip` 覆盖安装
  （不会动你的成品、声线、访客库、以及 `ncmapi\cookies\` 里已经配好的 Cookie）。
- **面板进程要重启**才会加载新页面和路由：双击根目录 `停止RVC.bat`，
  再双击 `启动RVC.bat`，然后刷新浏览器（只刷页面不够——路由在面板进程里）。
- **3002 也要重启一次**（换了适配器代码）：控制台「一键退出服务」再「一键开启」，
  或单独点网易云那行的「重启」。
- **已经配好的 Cookie 全部自动变成「默认账号」**，不用重新扫码或粘贴；
  想再加号就从账号行下面点「粘贴再加一个」。
- 不配任何新东西也能用：不开聚合时行为与 v2.2.0 一致；
  开了聚合只是多搜两家，点歌链路没变。
- 某家的号不想要了：在那一行点「退出」，其余照旧。

## 五、更新方式

控制台「版本」卡片点「检查更新」→「立即更新」，或在 Release 页面下载
`RVC-Cover-Station-Installer-v2.3.0.zip` 覆盖安装。

更新完同样要重开一次 `启动RVC.bat`——更新逻辑在 `updater.py` 里，
Python 只在启动时加载模块。
