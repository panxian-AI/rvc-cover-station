# RVC 翻唱站 v2.0.1 · 导入不再丢数据 · 依赖锁真正生效

这一版不加功能，只修两个「表面正常、实际在坑人」的问题——都是 v2.0.0 交付后复查时
翻出来的。**建议所有已经装了 2.0.0 的机器都更新。**

---

## 一、从备份导入会静默丢数据

**症状**：选了备份包、确认导入，页面提示「已用这份备份覆盖本机数据」，条数也对得上。
但过几秒刷新，数据又变回导入前的样子——有时是整份回去，有时少几条。没有报错，
备份列表里还留着「导入前自动备份」，人会以为是自己看错了。

**真因**：导入是「先写文件、最后才让内存跟上」，两步之间隔着一整段工作（写设置、
写成品索引、解压音频，带音频时要几十秒）。这期间巡队线程每 5~15 秒会 `flush()` 一次，
任何访客访问也会触发一次 `_save()`——它们写的是**导入前的内存**，于是把刚导入的文件
盖了回去。接口那边早就返回成功，所以谁也看不出出过事。

**改法**：写库不再由导入代码直接动文件，统一走 `guest.replace_db()`——换内存与落盘
在同一把锁里完成，中间插不进别人的写：

- `guest._load()` / `replace_db()` 共用一套 `_shape()` 归一化，不会两处规则各写一份；
- 失败回滚也走同一个入口（以前只还原文件，内存里还留着「导入后」的内容，下一次写盘
  同样会把它写回去）；
- 合并模式取「本机现在」改用 `guest.snapshot()`（内存深拷贝）：soft 写被节流的那两秒
  里文件比内存旧，按文件算会把刚发生的申请漏算。

**顺带修的**：`_save()` 失败（磁盘满、文件被占用）以前是 `except OSError: pass`，
写不进去当没发生，改动直接丢。现在保留脏标记等下次重试，并把原因通过 `/api/status`
暴露出来，概览页会显示红字提示。

**回归**：`e2e_dataio` 新增一段并发用例——导入期间每 10 毫秒模拟一次巡队写盘，断言
磁盘和内存都停在导入后的内容；回滚用例也补了「内存是否一起回滚」。

## 二、依赖锁在真实安装里是空转的

**症状**：控制台「概览」页从来不提示依赖漂移。哪怕手动 `pip install pillow --upgrade`
升到别的版本，页面依旧安静。

**真因**：三处都断开，缺一处都不行：

1. `一键安装.bat` 只搬了 `VERSION`、`README` 和三个 bat，**没搬顶层 `requirements.txt`**；
2. `updater.apply()` 只覆盖 5 个目录（dashboard / RVCSVC-API / ncmapi / setup /
   RVC-WebUI），根级文件被 `rel == top` 一律跳过，所以更新也补不上这份清单；
3. `deps.check()` 打不开清单时返回 `ok: True` + 「跳过核对」——页面拿到 ok 就当没事。

结果是这套机制只在「我手动 cp 过一份」的机器上有效，正是典型的「在我机器上是好的」。

**改法**：

- 安装器把 `requirements.txt` 一起复制到 `RVCSVC\`；
- 更新器新增 `ROOT_FILES = {requirements.txt, install.json}`，更新时一并落地（同样先备份）；
- 清单缺失不再返回 ok：`missing_file: true` + `ok: false`，概览页明确显示「安装目录里缺
  requirements.txt」，并且不给那句没用的 `pip install` 建议。

**同时加固**：更新包下载后先做整包 CRC 校验再覆盖。`apply()` 是边解压边写，以前包在
下载途中被截断时，前面几十个文件已经写进去了，走到坏的那条才抛异常——留下半新半旧的
代码。现在坏包直接换线路重试。

**回归**：`e2e_modules` 新增 D 段（安装 / 更新 / 核对三段是否真的连通）、
`e2e_ai_install` 新增「安装器必须带上依赖清单」、`e2e_market` 补了「坏包不当好包用」。

## 老用户怎么更新

正常一键更新即可。**更新完请重开一次面板**（托盘菜单「停止服务并退出面板」，再双击
`启动RVC.bat`）——`guest.py` / `dataio.py` 是面板进程里的模块，不重启还是旧代码。

更新后请确认一件事：`RVCSVC\requirements.txt` 是否存在。存在（更新器会补上）就说明
依赖锁已经生效；打开控制台「概览」页不再有黄色或红色提示，就是版本都对得上。

数据格式一个字节没变，v1.5.0 / v2.0.0 导出的备份包照样能导入。

## 验证

- 回归 **18 套 939 项全好**（`e2e_dataio` 84→90、`e2e_modules` 55→69、
  `e2e_market` 97→99、`e2e_ai_install` 62→64）
- 并发用例实测：导入期间每 10ms 写一次盘，磁盘与内存都停在导入后的 3 单；
  修复前同一场景会退回导入前的 1 单
- 依赖核对在本机实测：8 项全部 `ok`；清单缺失时返回 `missing_file` 而非沉默
