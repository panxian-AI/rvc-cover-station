# RVC 翻唱站 v2.2.0 · 音源支持网易云 / QQ 音乐 / 酷狗，自己选

> **症状**：想点的歌在网易云搜不到、或者搜到了也拿不到播放地址（VIP / 独家），
> 只能跟访客说「这首做不了」。而 3002 从第一天起就写死了只有网易云一家，
> 换平台得改代码。
>
> 这一版把音源做成**可插拔适配器**：现在有网易云 / QQ 音乐 / 酷狗三家，
> 每家独立 Cookie、独立登录态，默认用哪家你说了算，单次搜索也能临时换。
> 加第四家只需再写一个 120 行的模块。

## 一、为什么以前只有网易云

3002 那个服务本来就是「把歌名换成歌曲 ID 给插件用」的网易云专用代理：

- 搜索写死 `music.163.com` 的接口，`song_id` 就是网易云的纯数字 id；
- 队列、成品索引里存的也是纯数字 id；
- Cookie 只有一份 `ncm_cookie.txt`，只有一个「未登录」状态。

于是「换一家音源」不是加个开关的事：id 格式、取流方式、Cookie 字段、
登录态判定，四样全不一样。硬塞进一个文件里，最后会变成一堆
`if platform == ...` 散在各处。

## 二、这一版怎么改的

**1. 音源拆成一平台一个文件（`ncmapi/sources/`）**

```
ncmapi/sources/
  base.py       公共底座：HTTP（绕开系统代理）、CookieStore（按 mtime 热重载、
                原子写盘）、SourceError（分清「没登录」和「没版权」）、id 解析
  netease.py    网易云：cloudsearch 搜索 + enhance/player/url 取流
  qq.py         QQ 音乐：client_search_cp 搜索 + musicu.fcg 取 vkey
  kugou.py      酷狗：song_search_v2 搜索 + trackercdn 取流（key = md5(hash+kgcloudv2)）
  __init__.py   注册表 + 别名（163 / qqmusic / kg …），加平台只改这里一行
```

每个模块对外都是同一组名字：`search / song_url / song_detail / login_status`
加 `KEY / LABEL / COOKIE_HINT / STORE`。网关、面板、后端下载全部只认这组名字。

**2. 3002 加一个 `platform` 参数，老调用一个字都不用改**

```
/search?keywords=十年&limit=3                  → 网易云（默认，行为与以前完全一致）
/search?keywords=十年&limit=3&platform=qq      → QQ 音乐
/song/url?id=kugou-5146461A5717...             → 按 id 前缀自己认平台
/platforms                                     → 三家各自登录态一览
```

`song_id` 用**前缀**区分（`qq-0035Gve...` / `kugou-5146461A...` / 纯数字=网易云）。
分隔符特意用 `-` 而不是 `:`——后端会把 id 拼进成品文件名，Windows 不允许冒号，
两边一 sanitize 就对不上了。不带前缀一律当网易云，所以老队列、老成品索引、
AstrBot 插件传过来的纯数字 id 全部照旧能跑。

**3. 控制台：一家一行，点谁配谁**

概览页「服务状态」下面多了一栏「音源平台」：

```
网易云   ⚠ 未登录       [📱 扫码登录]  [粘贴 Cookie]
QQ 音乐  ⚠ 未配置       [粘贴 Cookie]
酷狗     未配置（免费曲可直接用）  [粘贴 Cookie]
```

- 网易云还是扫码（手机 App 扫一下确认），扫码被风控拦时可以展开粘贴框；
- QQ 音乐 / 酷狗点「粘贴 Cookie」，把浏览器里已登录页面的整段 Cookie 粘进去；
- 三家分别存 `ncmapi\ncm_cookie.txt`、`ncmapi\cookies\qq.txt`、
  `ncmapi\cookies\kugou.txt`，互不覆盖；保存前会校验标记键
  （`MUSIC_U=` / `qm_keyst=` / `token=`），粘错了当场拒绝，
  **不会把好用的旧 Cookie 冲掉**；写盘仍是 tmp + fsync + os.replace。

**4. 默认平台可以设，单次也能换**

- 全局默认：控制台「⚙️ 高级设置 → 默认音源平台」
- 单次指定：翻唱页与访客页搜索框旁的下拉，只影响这一次搜索
- 搜出来的结果行会标出平台名，点歌时按结果自带的平台走

**5. 下载/翻唱链路跟着平台走**

后端 `app_rvc.py` 取流时按 id 前缀分派：非网易云的曲子只走本地音源网关
（不再去试网易云的几个备用站，那些站没有这首歌）。落盘文件名仍用纯 id，
成品索引里的 `song_id` 保持原样，历史成品照样能试听、能复用。

**6. 失败要说得清楚**

以前所有取流失败都回一句「没拿到播放地址」。现在分两种：

- **没配 Cookie**（QQ 音乐匿名一律取不到流）→ 提示「去概览页音源平台配一下」，
  并说明配了之后能解决什么；
- **没版权 / 已下架 / 要会员** → 提示换一首，别去折腾 Cookie。

## 三、三家平台实测差别（别拿网易云的经验套）

| | 匿名能搜 | 匿名能取流 | Cookie 标记键 | 备注 |
| --- | --- | --- | --- | --- |
| 网易云 | ✅ | 只有免费曲 | `MUSIC_U=` | VIP / 独家要登录 |
| QQ 音乐 | ✅ | ❌ 一律空 purl | `qm_keyst=` | 上游策略，必须带 `uin` + `qm_keyst` |
| 酷狗 | ✅ | ✅ 免费曲 | `token=` | 免费曲匿名直接下到真音频（已实测） |

酷狗额外说明：Cookie 只能证明「填过」，不能像网易云那样查昵称确认「还有效」，
所以面板对它只显示「已配置」，不承诺一定可用。酷我音乐（`kuwo`）这版**没有接**——
它的搜索接口要先拿 csrf cookie 才不返回 `The request is illegal!`，留到下个版本。

## 四、老用户怎么办

- **不用重装**，控制台「版本」卡片点「检查更新」→「立即更新」即可；
  也可以下载 `RVC-Cover-Station-Installer-v2.2.0.zip` 覆盖安装
  （不会动你的成品、声线、访客库、**以及已经配好的 Cookie**——
  `ncmapi\cookies\` 已加入更新器的跳过名单）。
- **面板进程要重启**才会加载新页面和路由：双击根目录 `停止RVC.bat`，
  再双击 `启动RVC.bat`，然后刷新浏览器。
- **3002 也要重启一次**（这版换了代理代码）：控制台「一键退出服务」再「一键开启」，
  或单独点网易云那行的「重启」。
- 不配任何新 Cookie 也能用：默认平台仍是网易云，行为和以前一模一样。
- 之前配好的网易云 Cookie 继续有效，不用重新扫码。

## 五、更新方式

控制台「版本」卡片点「检查更新」→「立即更新」，或在 Release 页面下载
`RVC-Cover-Station-Installer-v2.2.0.zip` 覆盖安装。

更新完同样要重开一次 `启动RVC.bat`——更新逻辑在 `updater.py` 里，
Python 只在启动时加载模块。
