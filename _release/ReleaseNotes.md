## RVC 翻唱站 v1.1.5 · 长歌不再卡在「分离人声」这一步

**症状**：一首四五分钟的歌，点生成之后在「分离人声伴奏」这步失败，
日志里是一串 numpy 堆栈，最底下写着：

```
numpy.core._exceptions._ArrayMemoryError:
Unable to allocate 25.6 MiB for an array with shape (2, 13434148) and data type bool
```

看着像代码写错了，其实跟模型没关系——自己导入的声线是好的，短一点的歌也正常。

**原因**：UVR5 分离人声这一段，把整首歌的频谱一次性摊在内存里算。
实测一首 4 分 40 秒、48kHz 立体声的歌，**进程峰值提交内存到 6.5GB**。
机器上没那么多余量时，连 25MB 都申请不到，numpy 就直接把这句话甩出来了。

---

### 改了什么（都是把中间产物早点放掉，不换算法、不改音质）

| 位置 | 原来 | 现在 |
|---|---|---|
| 频谱合成缓冲区 | `dtype=complex`（complex128） | `complex64`，每个频带直接省一半 |
| 频谱合并 | 建成 C 序再整份转成 Fortran 序 | 直接按 Fortran 序建，省 270MB |
| STFT 左右声道 | 两份拷贝再叠成数组 | 预分配后逐声道填，省约 400MB 瞬时 |
| 分离推理 | 归一化后的幅度谱和相位常驻内存 | 归一化只做一次、相位只留一种，省约 280MB |
| 频带处理 | 最高频的切片是「视图」，一直钉住整块频谱 | 改真拷贝；各频带用完立即释放；伴奏写盘后马上丢 |

**输出等价性**：随机数据下逐位比对，频谱生成、合并、合成三处**最大差 0.000e+00**；
另外拿 20 秒片段在 CPU 上跑完整的新旧两版，人声与伴奏最大差 3.05e-5
（正好是 16bit 的 1 个最低位，听不出来）。

---

### 顺带修的三个问题

1. **内存真的不够时，不再甩堆栈**。改成告诉你能怎么做：关掉浏览器多余标签/游戏/剪辑软件再点一次、换 3 分钟以内的歌、或者先「一键停止」再「一键全部启动」清掉残留内存。分离前日志里会多一行「分离前可用内存 xxx MB」，出问题看这个数就能判断。
2. **失败不再留垃圾**。以前失败会在安装目录留下一整首歌的 wav（几十 MB），现在无论成败都清掉。
3. **自己导入的模型终于用上 index 了**。日志里那句「未找到匹配的 index（最高相似度: 0.32）」是个 bug：WebUI 生成的 index 前面固定带 `added_IVF<数字>_Flat_nprobe_<数字>_`、后面带 `_v2`，一长串无关字符把相似度拉到 0.4 的判定线以下，`index_rate` 等于一直是白设的。现在先把文件名归一化再比，配套的 index 能命中 1.00，音色更像。无关的 index 仍然不会被误认。

**已经装好的用户**：程序自更新到 1.1.5，更新完控制台重启一次就生效，
不用重新装模型、也不用重新装声线。

**新装用户**：直接下载本次的安装包，装完就是 1.1.5。

如果更新完界面还是旧的，关掉控制台窗口，重新双击「启动RVC.bat」。
