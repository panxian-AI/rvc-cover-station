# RVC 翻唱站 v1.0.7 · 安全加固（白名单防冒用 + 公网暴露面收敛）

这一版不加新玩法，专治两种真实的滥用：**一堆设备顶着白名单身份刷单**，和**隧道地址被扫到后乱翻别的东西**。

## 下载

  内含 `一键安装.bat` 与 `安装说明.txt`；程序代码与依赖由安装器自动下载（长效模式：默认拉 main 最新）。
- 已经装过的：控制台打开会提示有新版本，点「立即更新」即可，**模型 / 成品 / 访客记录 / 白名单 / 设置都不动**。

## 一、白名单：从「三要素」升级到「四要素 + 额度 + 自动告警」

原来白名单只认 `访客 id + 设备指纹 + IP`。问题在于**设备指纹是同款设备完全一样的哈希**，而且由前端自己上报——同一 WiFi 下的另一台同型号手机，或者拿到别人下载链接里 `gid` 的人，就能顶着白名单身份提交。

现在改成：

1. **设备密钥（dv）**：批准时额外绑定一枚 48 位随机密钥，只存在访客浏览器 localStorage，不进 URL、不进 Cookie，服务端只存它的 SHA-256。抄走 `gid` 和指纹也没用，必须拿到那台设备本身。
2. **每身份额度**：每天最多 12 单、每小时 6 单、两次提交间隔 ≥20 秒。身份真被抄了也刷不穿。
3. **自动挂起 + 告警**：同一身份 24 小时内出现 ≥3 个不同指纹、≥4 个不同网络，或指纹对不上 ≥10 次，自动暂停该白名单（不再免审批），控制台顶部弹出红色告警，附原因和一键「恢复」。
4. **申请侧再补一刀**：同一台设备（同一设备密钥）换 `gid` 重复申请会被当场挡下。

老版本批准的白名单条目没有设备密钥，仍然按原规则可用，控制台会标成「仅指纹」——建议让对方刷新页面重新申请一次，绑上密钥才防得住冒用。

## 二、公网暴露面：改成 fail-closed

以前是「公开路径写在前面，管理接口在后面统一拦」。现在反过来：**公网只认一份明确的白名单**，其它一律拒绝，并且以后新加接口也默认不暴露。

- 公网能碰到的只有：访客页 `/`、`/guest`，以及 `/api/guest/` 下的访客接口、两个提交通道；
- `/panel`、`/cover`、`/api/admin/*`、`/api/status`、`/api/update/*`、`/.env` 之类一律 403，并记入 `security.log`；
- **Host 头校验**：恶意域名解析到 `127.0.0.1`（DNS rebinding）也拿不到控制台——Host 必须是本机名 / 回环 / 本机网卡 IP；
- **探测封禁**：同一 IP 10 分钟内碰 20 次非公开路径，直接封 30 分钟（连访客页也打不开），控制台可看到列表并一键解除；
- **一键暂停公网访问**：控制台「安全」卡片里的开关，按下后公网只剩一个维护页，本机控制台照常可用——被刷、被骚扰时能立刻止血。

## 三、顺手堵掉的本机暴露

- 后端 **3333**（翻唱 API）和 **WebUI 7865** 原来都绑 `0.0.0.0`，没有任何登录，等于同一个 WiFi 下谁都能改模型、跑推理。现在默认只绑回环；确实要用手机访问 WebUI，再设环境变量 `RVC_BIND=0.0.0.0`。
- 隧道本身没变（还是只转发 8899），变的只是 8899 后面能碰到什么。
