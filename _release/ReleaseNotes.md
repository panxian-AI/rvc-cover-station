# RVC 翻唱站 v2.0.0 · 拆包重构 · 控制台分多页 · 依赖锁版本

这一版不加新玩法，专门收拾「越写越难改」和「上游一升级就出问题」这两件事。
功能一个没少，行为基本照旧（页面地址多了一层归类），但代码和目录都换了骨架。

## 一、panel.py 从一个 2318 行的巨无霸，变成 200 行的入口

**症状**：想改一个接口，要在两千多行里翻；翻唱页、队列、审批、备份、更新全塞在同一个
文件的 if 链里，改 A 碰到 B 是常事。新人（或 AI）接手时，光看清结构就要半天。

**改法**：按「谁依赖谁」拆成一层一层的包，下层不许 import 上层：

```
panel.py              入口：起服务、挂托盘、出错提示（~200 行）
panelkit/
  core.py             常量 / 路径 / 可选子模块 / 页面缓存 / HTTP 小工具
  security.py         公网白名单、探测封禁、安全日志
  sysinfo.py          端口 · 进程 · GPU · 网卡 · 日志
  services.py         服务启停、启动前体检、公网隧道
  pages.py            页面登记表 + assets/ 静态资源
  trayapp.py          任务栏图标
  routes_get.py       GET 路由
  routes_post.py      POST 路由
  server.py           PanelServer + Handler 基类 + 分发
```

几个刻意的设计：

- **老代码不受影响**：`import panel` 照样能拿到 `panel.collect()`、`panel.stop_all()` 等
  全部名字（`panel.py` 重新导出）。`panel.SERVICE_PORTS = {...}` 这种**赋值**也会转发到
  真正持有它的子模块——不然测试里改的只是门面，跑的还是旧值。
- **不让循环导入出现**：`core` 是最底层，连 `security` 都不 import；`services` 用到端口
  就 `from .sysinfo import ...`，方向永远朝下。回归里有一条专门扫这个。
- **路由还是那条 if 链**：没为了「优雅」改成注册表工厂——链式写法一眼能看出「这条路径
  在不在、在谁前面」，而顺序在这个项目里是有意义的（`/api/data/` 必须排在
  `/api/admin/` 通配之前）。

## 二、控制台从一页拆成四页

**症状**：一页 13 张卡片，服务、队列、审批、白名单、模型、设置、备份全在一条长滚动里。
手机上要划很久，「我现在这一屏到底是什么事」也不清楚。

**改法**：按「你在干什么」分页，顶部导航随时切换：

| 页面 | 地址 | 放什么 |
| --- | --- | --- |
| 概览 | `/` | 服务状态与一键启停、版本与更新、公网地址、启动日志 |
| 任务 | `/console/tasks` | 制作队列、自助翻唱任务、待审批、申请记录（含访客记录） |
| 访客 | `/console/guest` | 白名单、验证码解锁、公网安全（暂停/解封） |
| 设置 | `/console/settings` | 高级设置、模型市场入口、模型导入、数据备份与迁移 |

- 样式与脚本收到 `dashboard/assets/`（`console.css` + 每页一个 js），页面只留结构。
- 静态资源走新路由 `/assets/*`：只认一层目录 + 白名单后缀，`../` 和 `.py` 一律 404。
- 改完 css/js **刷新浏览器就生效**，不用重启面板（响应头 `no-store`）。
- 每个分页可以独立打开、独立收藏、独立刷新。
- 原有的模型市场、模型管理、监控面板、自助翻唱、访客页一个没动。

## 三、顶层 requirements.txt 锁死版本

**症状**：`edge-tts>=7.0`、`gradio-client>=1.13`、`pillow>=10.0` 这种下限写法，等于把
「下次装到哪一版」交给运气。这三个包都改过不兼容的地方（TTS 接口、字段名、图像 API），
一旦被顺手升级，表现是「以前能用的功能突然不行」，报错完全看不出跟升级有关。

**改法**：

1. `requirements.txt` 全部 `==`，连 `urllib3` / `certifi` / `charset-normalizer` / `idna`
   这些传递依赖一起钉住。
2. 新增 `dashboard/deps.py`：读 `requirements.txt`，比对机器上**实际装的版本**。
   - 控制台「概览」页会出一条黄色提示：装的是几、应为几，外加一条可以直接粘贴的
     修复命令（用当前解释器，不指望 PATH 里的 python）。
   - 单独查：`RVCSVC\apienv\Scripts\python.exe dashboard\deps.py`，退出码 0/1，方便脚本化。
   - 结果缓存 5 分钟，不会每 8 秒轮询都去问一次包管理器。
3. 升级流程写进文件注释：先 `--upgrade` → 跑 e2e → 全绿再改版本号 → 随版本发。

反过来的保护也在：核对**不会**拦住面板启动。差版本只是提示，不影响你今天用。

## 四、顺手修掉的

- `legacy_page.html`：老监控页那一大段 HTML 原来以 `PAGE = r"""..."""` 硬编码在 panel.py
  里（340 行），现在独立成文件，改样式不用碰 Python。
- `ncm_preflight()` / `webui_preflight()` 挪到 `sysinfo.py`（它们只是看文件在不在），
  这样 `collect()` 不用反过来依赖 `services`。
- 控制台「概览」页多了依赖漂移提示位；`/api/deps` 接口只对本机开放。

## 从 v1.5.x 更新

正常一键更新即可，**数据格式一个字节没变**（`guest_db.json` / `advanced_settings.json` /
`covers/index.json` 全部照旧，v1.5.0 的备份包也能直接导入）。

更新完**必须重启一次面板**（托盘菜单「停止服务并退出面板」，再双击 `启动RVC.bat`）：

- `panelkit/` 是全新目录，`panel.py` 只剩入口，旧进程里跑的还是旧代码；
- 不重启的话打开控制台会看到旧页面，会以为「更新没生效」。

重启后地址变化：

- 原 `/` = 概览（跟以前一样是控制台首页）
- 任务 / 访客 / 设置 分别是 `/console/tasks`、`/console/guest`、`/console/settings`
- 以前收藏 `/#xxx` 之类锚点的，直接点顶部导航即可
