# RVC 翻唱站 v2.1.2 · 结构整理（功能同 v2.1.1）

> **这一版没有新功能、也没有修用户能感觉到的 bug。** 做的是三件「以后改起来更快、
> 更不容易改坏」的事：把四个页面各存一份的前端工具函数合成一份、把 1246 行的
> `dataio.py` 拆成三层、把全量回归接进发版流程（不绿就不许发）。
>
> 为什么值得更新：`dataio.py` 是**导入备份**那条链路的全部实现，拆开之后这条路
> 再改就有 90 项专用用例兜着；发版门禁则保证「说全绿」这件事以后是跑出来的，
> 不是拍脑袋说的。
>
> 功能与 v2.1.1 完全一致。不想更新也不会有任何影响。

---

## 一、前端那四个 `$ / toast / esc`，原来是四份

**症状**：没有症状。但这类重复一旦有人只改一处，四个页面的行为就会不一致——
实际上已经发生了一半：`esc` 在拼接 HTML 时**不转义单引号**，所以需要一个专门
处理内联事件的变体 `jsq`，而这个变体只有访客页有定义，另外三个页面想用也没有。

**真因**：v2.0.0 把原来的单页拆成四个页面时，每页各自复制了一份「头部小工具」，
之后各改各的。

**改法**：新建 `assets/common.js`，`$` / `toast` / `esc` / `jsq` 只留这一份，四个
页面在自己的脚本之前加载它。顺手把任务页 8 处内联事件里的 `esc` 换成 `jsq`：

```js
onclick="decide('approve','${esc(r.id)}')"   // 名字里一个 ' 就把整句 JS 断掉
onclick="decide('approve','${jsq(r.id)}')"   // \x27 到 JS 手里才变回单引号
```

说清楚：现在的单据 id 是定长十六进制，**正常的名字触发不了这个问题**，这属于
防御性修复，不是「修好了一个你遇到的 bug」。

**回归**：`e2e_modules` 新增 14 项——公共库能取到、四页都**先**加载它、
页面脚本里不许再定义同名函数、内联事件里不许出现 `esc(`。

## 二、`dataio.py` 1246 行 → 门面 60 行 + 三层实现

**症状**：还是「没有症状」，但这份文件是「导出备份 / 导入备份」的全部实现，
最长的单个函数接近 300 行，改一处要在一千多行里翻半天；`check()` 和 `apply()`
共用一个文件，读到一半经常忘了自己在看哪条路径。

**真因**：功能是一年年长上去的，从「导出一个 zip」长到「预检 + 合并 + 回滚 + 解压
炸弹防护」。

**改法**：拆成 `dashboard/dataiokit/`，依赖严格单向：

| 文件 | 职责 | 行数 |
|---|---|---|
| `core.py` | 常量、路径适配、锁、sha/体积/条数之类的小工具 | 303 |
| `backup.py` | 打包导出、备份列表/删除/裁剪、选文件、打开目录 | 341 |
| `restore.py` | 只读预检、合并、规整、落盘与失败回滚 | 641 |

`dataio.py` 保留为薄门面，`import dataio` / `dataio.export()` 这些老写法一个字都不用改。

**拆包最容易踩的坑**（都踩了，都堵了）：

1. **函数里用了没 import 的全局名**——代码看着没问题，跑到 `summary()` 才
   `NameError: _counts`。第一版就漏了一个。现在 `e2e_modules` 用 `symtable`
   扫一遍「函数当全局用、模块却没定义也没 import」的名字，缺一个就红。
2. **替换内部函数失效**——测试靠 `dataio._write_atomic = boom` 来验「写盘失败要
   整体回滚」。拆开后真正被调用的是 `restore.py` 里那一份，只改门面等于没改，
   测试会「假装通过」。门面装了转发器，`dataio.X = v` 会同步到所有持有 X 的子模块
   （和 v2.0.0 拆 `panelkit` 时 `panel.X` 的处理同一套）。
3. **源码断言读到空壳**——`e2e_modules` 原来直接读 `dataio.py` 找
   `_replace_guest(merged)`，拆完那行搬进 `restore.py` 了，断言会假红。改成读
   「门面 + 包内全部文件」。

**回归**：`e2e_dataio` 90 项全过（含「写盘失败整体回滚」「导入时有人来访也不冲掉」
两条最硬的）；`e2e_modules` 新增分层单向、门面 61 个老名字齐全、赋值转发三项。

## 三、发版流程：「说全绿」以后必须是跑出来的

**症状**：v2.1.0 发出去时宣称「19 套 966 项全绿」，实际是 969 项、2 项失败。
原因是打包时没重跑全量，也没有任何东西拦着「没跑测试就发版」。

**改法**：`_release/create_release.py` 开跑的第一件事变成**跑全量回归**：

```
[门禁] 全量回归：...python.exe run_e2e.py --repo <仓库根> --strict -q
...
套数 19（跳过 0）· 断言 1005 项 · 通过 1005 · 失败套数 0
RESULT: PASS
[门禁] 回归全绿，继续发布
```

不绿直接退出，不会创建 Release、不会上传资产。确实需要跳过（比如只补一个资产）
时显式设 `RVC_SKIP_E2E=1`，会打印一行「这次没有跑全量回归」。另外加了 `--dry-run`：
只跑门禁、不真发版，发版前想先确认「能不能发」时用。

## 四、现在跑一遍是什么样

```
19 套 · 1005 项断言 · 全绿 · 约 113 秒
```

自己跑：

```bat
cd 安装目录\RVCSVC\dashboard
..\apienv\Scripts\python.exe run_e2e.py --repo <仓库根> --strict
```

> `--repo` 只在「代码不在安装目录里」时才需要（比如在仓库副本里跑）。安装目录里
> 跑的机器，`e2e_ai_install` 会因为没有安装器源码自动跳过，并显眼列在 SKIP 里。

## 老用户怎么更新

1. 控制台右上角会提示有新版本 → 点「一键更新」（面板会自己下载、校验 CRC、
   替换文件、必要时回滚）。
2. 更新完**重开 `启动RVC.bat`**。这一版新增了 `dataiokit/` 目录，Python 只在启动时
   加载模块，不重开会继续跑旧代码（页面能打开但「数据备份」卡片会用旧逻辑）。
3. 或者直接下新版一键安装包，装在原目录即可（会自动保留个人数据）。

## 这次没做的

- `guest.py`（1884 行）、`market.py`（1117 行）仍是单体。这两块的拆分风险和测试
  覆盖面都比 `dataio.py` 大，留到下一次单独做。
- 更新包只有 CRC 没有签名（下载线路含第三方加速镜像），理论上中间人可以换包。
- 后端 `predict` 没有整体超时，一次假死会占死一个并发槽。
- 仍然没有 CI，回归靠人手动跑（但门禁已经把「没跑就发版」堵死了）。
