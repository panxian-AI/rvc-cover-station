# RVC 控制台（访客点歌 + 审批 + 状态监控）

一个本地网页，用来在**不打开 AI 助手**的情况下查看和管理 RVC 翻唱服务。
公网开放时，外人只看到「点歌页」，看不到任何管理功能。

## 怎么启动

双击：`E:\启动RVC.bat`（移动硬盘根目录；桌面上那个「启动RVC翻唱.bat」也是转发到它）

起来后的入口，都在 8899 端口上：

| 地址 | 谁能进 | 干什么 |
|---|---|---|
| `/`（本机打开） | **只认这台电脑** | **控制台**：服务开关、公网地址、制作队列（排序）、待审批、申请记录、访客记录 |
| `/`（公网 / 局域网打开） | **任何人** | **访客点歌页**：搜歌（要验证码）→ 选声线 → 提交申请 → 等批准 → 下载 |
| `/guest` | 任何人 | 访客页固定地址（和公网 `/` 看到的一样，本机可拿来预览） |
| `/panel` | 只本机 | 监控面板：服务开关、模型清单、日志、缓存 |
| `/cover` | 只本机 | 自助翻唱页：自己直接跑，不用审批 |

**管理没有密码、没有独立审批台**：panel 只认「这台电脑的 127.0.0.1 直连」。
公网（隧道）、局域网（手机 / 其它电脑）访问管理页面和接口一律 403，
就算知道端口也进不去——想管理就必须坐在跑面板的这台电脑前。
`/admin`、`/login` 已取消，旧书签会跳回首页。

- 服务开关在**控制台首页**和监控面板都有（「⚡ 一键开启服务」）；收工去监控面板点「⏹ 一键退出服务」
- 访客提交后**不会自动跑**，要你在控制台「待审批」里点「✓ 批准入队」；批了之后进队列，
  GPU 一次跑一单，做完自动接力下一单。批准后约 1~4 分钟出片，访客页面每 5 秒自动刷新，
  完成后直接出现下载按钮。

关闭那个黑窗口 = 关掉面板，**后端不受影响**（所以退出请点按钮，别直接关窗）。

## 让外网的人也能用（内网穿透）

双击：`E:\启动RVC-公网.bat`

它比普通启动多三件事：拉起全部服务 → 开 Cloudflare 隧道 → **在窗口里打印一个
`https://xxxx.trycloudflare.com` 地址**。把这个地址发给他就行——**访客页不需要密码**。

- 访客打开链接看到的就是点歌页（搜歌 / 选声线 / 提交 / 下载），看不到面板、缓存和管理功能。
- **每次搜索都要输一道图像验证码**（2026-11 加）：看图输 4 个字符才能搜；验证码一次性、
  绑定访客会话、3 分钟过期，同一 IP 连错 8 次锁 10 分钟。图片是真 PNG 位图（无文字层），
  字符随机旋转 + 干扰线，防脚本刷搜索接口。没搜过验证码就调不了搜索，也就拿不到歌，
  自然也提交不了申请。
- 他提交的申请出现在你的**控制台**里，带**他的 IP、地区、设备、提交时间**；你批准后才会开跑。
- 控制台往下翻有「访客记录」：谁来过、来自哪里、用什么设备、来过几次、
  搜索了几次、提交了几单。
- **管理只认本机**：公网 / 局域网访问 `/`、`/panel`、`/cover` 和全部管理接口一律 403，
  没有密码可输（密码登录已在 2026-11-02 移除）。
- 隧道地址**每次重启都会变**（Cloudflare 临时隧道特性）；关掉窗口 = 公网断开，
  本机和局域网不受影响。想要固定域名得用 Cloudflare 账号 + 自有域名。
- 隧道走 Cloudflare 边缘，真实 IP 从 `CF-Connecting-IP` 头取（cloudflared 本地反代来源恒为
  127.0.0.1，不能按来源 IP 判断本地/公网，否则公网会被当成本机放行）。

> 提醒：批准就等于让对方的单子占用你的显卡。不在电脑前时把公网窗口关掉最省心。
> 数据落在 `dashboard\guest_db.json`（访客 + 申请记录），想清空直接删这个文件再重启面板。

## 这个页面能干什么

### 1. 告诉你手机插件该填哪个地址

顶部两张卡片就是这个：

**① RVC API Gradio 后端服务地址** → `http://电脑IP:3333/`（以 `/` 结尾别漏）

**② 网易云音乐 Node.js API 地址** → `http://电脑IP:3002`（本地服务，不要用 https）

你两台机子用热点共享、有时又接普通网络，**IP 会变**，所以每次换网络后打开这个页面，抄上面的地址填进插件就行。

> 为什么自己跑一个 3002？原先填的公共实例 `wyy.xhily.com` 已经挂了（从电脑上握手也是
> `TLS alert 40 handshake_failure`），而 vercel 系的公共实例国内连不上。
> 本地这个服务直接转发网易云自己的搜索接口，不走 TLS、不限流、断网恢复也快。

右侧会顺带显示：
- 局域网内 3333 现在能不能访问（✅ / ⚠️）
- 本地网易云 API(3002) 起没起
- 当前网关是谁（热点共享时那就是另一台机子）

### 2. 看三个端口是不是开着

| 端口 | 服务 | 说明 |
| --- | --- | --- |
| 3333 | 翻唱后端 RVCSVC-API | 插件真正调用的服务 |
| 7865 | RVC WebUI | 换声推理引擎，3333 依赖它 |
| 3002 | 本地网易云搜索 API | 插件把「歌名」换成「歌曲 ID」用，见下方说明 |
| 8899 | 本控制台 | 就是这个页面 |

每个都显示 PID 和进程名，后面有「启动 / 停止 / 重启」三个按钮。

#### 3002 要不要启用登录态（VIP 音源）

默认是**匿名模式**，只能拿非 VIP、非独家曲目。VIP 曲目会返回 `url: null`，插件端表现为「下载失败 / 没拿到播放地址」。

启用方法：**双击 `ncmapi\设置网易云Cookie.bat`**，在弹出的窗口里按步骤粘贴 Cookie（窗口会自动提取
`MUSIC_U`、当场检测登录是否生效），保存后重启 3002，启动窗口会显示 `登录态: ✅ 已启用`。
也可以手动编辑 `ncmapi\ncm_cookie.txt`（参考同目录 `ncm_cookie.example.txt`）。

- 能解决：VIP 曲目、部分独家曲目拿不到地址
- 不能解决：已下架、无版权、地区限制的曲目（这些连 VIP 也没用）
- 注意：Cookie 等同登录凭证，别外传、别提交 Git（已在 `.gitignore` 里排除）；改密码或别处退出登录后会失效，需重新取

### 3. 一键启停（推荐用这个）

页面最上面有一条总控，两个大按钮：

- **⚡ 一键开启服务** —— 依次拉起 WebUI(7865) → 后端(3333) → 网易云(3002)。
  它**会等到三个端口都真的就绪才返回**（约 70~100 秒），已在跑的服务自动跳过。
  点了就能走开，回来时状态灯是「全部在线 3/3」。
- **⏹ 一键退出服务** —— 按 后端 → 网易云 → WebUI 的顺序停掉，**并关闭本面板**。
  拔移动硬盘、玩游戏、想让显存空出来时用它。关掉后再开，双击「启动监控面板.bat」。

下面「端口与进程」卡片里还有两个细粒度按钮：

- **启动缺失的服务** —— 只补没起来的（比如 WebUI 崩了，后端还在跑）
- **仅停服务（面板留着）** —— 停三个服务但面板不关，方便继续看状态

> ⚠️ 顺序很重要。如果先起 3333 后起 7865，后端启动时加载不到模型列表，插件那边就看不到 `deepseek.pth`。
> 单点 3333 的「启动」时，如果 7865 还没起来，面板会直接拦住并提示你先起 WebUI。

**刚点开启就点退出会怎样**：后端启动要 20 秒，这期间端口还没监听。
面板会额外记住自己拉起的子进程 PID，所以即使端口没开也能把正在启动的进程杀掉，
不会留下占显存的后台进程（这条实测过）。

### 4. RVC 状态

- 翻唱后端 / 换声引擎 各自的健康状态
- 可用模型（读 `E:\RVC-Data\RVC-WebUI\assets\weights\` 里的 `.pth`，带文件大小）
- 当前生效的索引 —— 从后端日志里抓最后一次「索引：xxx」。
  如果这里显示「（还没跑过转换）」，说明启动后还没执行过翻唱，跑一首就会显示出来
- 索引文件列表（`logs\` 与 `assets\indices\` 下所有 `.index`）

### 5. 显卡

利用率、显存占用、温度，3 秒刷新一次。翻唱时能直观看到显存在涨。

### 6. 后端日志

直接显示最新那个 `api_rvc*.log` 的尾部十几行。翻唱失败时先看这里。

## 出问题时对照

| 现象 | 原因 |
| --- | --- |
| 插件报 `Parameter xxx is not a valid key-word argument` | 后端 API 端点没暴露这个参数名。看 `http://127.0.0.1:3333/gradio_api/info` 的 `/convert` 参数清单，缺哪个就在 `app_rvc.py` 的隐藏 API 按钮 inputs 里补上 |
| 插件报 `'<' not supported between instances of 'str' and 'int'` | 插件把某个参数按 schema 传成了字符串（典型是 `index_rate='0.75'`），而后端把它绑在 `gr.Slider`/`gr.Number` 上，gradio 预检边界时拿字符串比数字直接崩。隐藏组件必须用 `gr.Textbox`，在 `convert()` 里自己 `float()` |
| 插件报 SSL 握手失败 / Cannot connect to host | 插件里还填着 `https://wyy.xhily.com`。改成 `http://电脑IP:3002` |
| 插件报 `Decoding failed. ffmpeg returned error code: 1` 且末尾 `Invalid data found when processing input` | 下载源把 HTML 页面/JSON 错误当成音频写进了文件。后端已改为**只从本地 3002 取直链**，且下载后校验文件头（`ID3`/`RIFF`/`fLaC`/`OggS`），不合规就自动换下一个源。若仍出现，看后端日志里 `⚠️ 源 xxx 没给音频（头部=...）` 那行 |
| 插件报 `下载失败（已尝试: ...）` | 分两种：提示「3002 连不上」→ 服务没启动；提示「没拿到播放地址」→ 这首歌是 VIP 专享/无版权/已下架，换一首 |
| 翻唱出来只有几十秒，或者后端日志出现 `只下到 45 秒，但这首歌实际 326 秒` | 匿名状态下载 VIP 曲目只给 30~45 秒试听片段，接口仍然返回 200。按上面「启用登录态」配好 Cookie 即可拿到整首 |
| 插件报 `TimeoutError` / `asyncio.exceptions.CancelledError`，堆栈里有 `fetch_data` / `_request` / `sock_connect` | **搜歌请求根本没到电脑**（3002 的 access.log 里没有对应记录）。九成是手机和电脑不在同一网络：电脑连了家里 WiFi（192.168.66.x）而手机还在热点（192.168.202.x），或反过来。先对齐网络，再把插件里两个地址（3002 搜歌 + 3333 后端）改成电脑当前 IP。**电脑端日志有没有收到请求是分水岭：日志没记录 = 网络不通；有记录 = 服务问题** |
| 插件能连但搜不到歌 | 3002 服务没开，看本页 3002 是否「运行中」 |
| 插件报连接失败（3333） | 本页顶部地址与插件里填的不一致（换过网络），或 3333 没开 |
| 插件看不到模型 | 起服务顺序反了，点「⚡ 一键开启服务」 |
| 面板显示 7865 未启动 | WebUI 没起，3333 收到请求也换不了声 |
| 手机打不开 8899 / 3002 | 手机和电脑不在同一局域网，或被防火墙拦了 |
| 插件看不到模型 / 后端报「系统找不到指定的路径」/ 模型列表为空 | **移动硬盘没插，或者盘符不是 E:**。打开「此电脑」看 `E:\RVC-Data` 在不在；盘符被改成 F/G 时要在磁盘管理里改回 E |
| 一键启动耗时明显变长、日志卡在「正在加载模型」 | 机械硬盘休眠被唤醒（首次访问 3~8 秒），等一会就好，不是故障 |

## 加新模型（音色）

三个文件要放到正确位置，名字必须**互相对应**，否则会加载不出索引（音质变糊但不报错）：

| 下载到的文件 | 放到 | 说明 |
| --- | --- | --- |
| `xxx.pth` | `E:\RVC-Data\RVC-WebUI\assets\weights\` | 模型权重，**必需**，命名随意（如 `luotianyi.pth`） |
| `add_xxx.index` 或 `xxx.index` | `E:\RVC-Data\RVC-WebUI\assets\indices\` | 检索索引，强烈建议。文件名要包含模型名，如 `luotianyi_added.index` |
| `xxx.npy` | `E:\RVC-Data\RVC-WebUI\assets\npy\` | 训练特征文件，**推理用不到**，只有想继续训练才需要 |

放好后不用重启后端，手机 `/rvc 歌名` 时在模型列表里就能选到（后端每次调用都会向 WebUI 重新拉取模型列表）。

命名规则：后端用**文件名相似度**匹配索引（阈值 0.4）。`luotianyi.pth` 配 `luotianyi_added.index` 得分 0.75 能命中；但如果模型叫 `luotianyi.pth` 而索引叫 `vocal_v3_final.index`，就会匹配不上。看到日志里 `未找到匹配的 index（最高相似度: xx）` 就是这个问题。

怎么确认模型是 v1 还是 v2、能不能用：v1 的 `enc_p.emb_phone.weight` 是 `(192, 256)`、索引 256 维；v2 是 `(192, 768)`、索引 768 维。**模型和索引的维度必须一致**，混用会失败。

## 验证码 v2：一次验证、十分钟免重复（2026-11-02 第四轮）

访客搜索的验证机制从「每次搜索都要看图」升级为：

1. **一张图可以输错 2 次**：打错字不再立刻作废，第三次才换图（服务端计数，不是前端摆设）。
2. **通过后发「通行证」**：10 分钟内、最多 12 次搜索，同一访客连续搜歌**不用再输验证码**。
   通行证绑访客 Cookie + 来源 IP，换设备/换网络立刻失效，伪造直接 400。
3. **图片更好认**：字更大、噪点减半、旋转收窄到 ±18°，肉眼一遍过的概率高很多；
   防机器的能力靠限流和锁补（见下），不靠把图做人看不清。
4. **防滥用不放松**：
   - 空**关键词**的请求不再消耗验证码；
   - 同一 IP 取图限 40 张 / 10 分钟；
   - 同一 IP 搜索总闸 50 次 / 10 分钟（通行证 12 次之外再兜一层）；
   - 猜错阶梯锁定：连错 6 次锁 1 分钟 → 9 次锁 3 分钟 → 12 次锁 10 分钟。

涉及文件：`captcha.py`（全部逻辑）、`guest.py`（`/api/guest/search` 接受 `ct`+`ca` 或 `cp` 通行证）、
`guest_page.html`（验证通过显示绿色「✓ 已通过验证」条，通行证存 `sessionStorage`，关标签页才失效）。
回归测试：`e2e_security.py` 第 [13][14] 节，全套 37/37 通过。

  是故意保留的——`webui.py` 第 62 行在启动时就 import 它，删掉整个目录 WebUI 直接起不来。
- 想恢复训练：重新下载 `pretrained` / `pretrained_v2`（HuggingFace `lj1995/VoiceConversionWebUI`）
  放回 `E:\RVC-Data\rvc_assets\`，再把 `训练_继续.bat` 的路径指回来即可。
- `weights_checkpoint_backup` 里还有 8 个 deepseek 训练中途的 checkpoint（e25~e200，440 MB），
  只对「接着上次继续训练」有用，不训练就是死重量。

## 关于音量（削波保护）

不同模型输出电平差别很大（v1 的洛天依比 deepseek 高 2 dB 以上），直接和人声叠加会超过 0 dBFS，导出后是**硬削波**——听感刺耳、发糊，而且事后降音量也救不回来。

现在后端会在叠加前后各做一次处理：

```
🔉 人声+伴奏峰值合计 6.02 dBFS，先各自降 6.92 dB 预留 headroom   ← 叠加前，防止 pydub 硬截断
🔉 混音峰值 -1.54 dBFS -> 调整 +0.54 dB 到 -1.0 dBFS            ← 叠加后，把电平提回来
```

看到 `混音峰值 ... 调整 ... 到 -1.0 dBFS` 就是正常的。如果日志出现 `⚠️ headroom 预判跳过`，说明该段异常但会继续跑。

代价是成品**听起来比网上商业歌曲轻一点**——因为峰值压到 -1 dB 而没做压缩/限幅，动态保留了。想更响就得加限幅器，那会引入轻微失真，默认不做。

## 安全加固（2026-11-02 第二轮）

公网开放后做过一次完整审计，**先找漏洞再补**。回归脚本：

```
E:\RVC-Data\RVCSVC\apienv\Scripts\python.exe E:\RVC-Data\RVCSVC\dashboard\e2e_security.py
```

它自己在 8898 起临时实例，跑完自动还原 `guest_db.json`，不会动正在用的 8899。当前 **26/26 通过**。

| 漏洞 | 怎么被利用 | 已改成 |
|---|---|---|
| 无条件信任 `CF-Connecting-IP` / `X-Forwarded-For` | 同一 Wi-Fi 下的设备直连 8899 伪造头，每次换 IP 绕过「错 5 次锁 10 分钟」 | 只有**连接来自 127.0.0.1**（即真 cloudflared）才信任转发头；另加全站失败计数（30 次/10 分钟）兜底 |
| 密码模块导入失败时 `_guard` 直接放行 | 一个语法错误就让面板裸奔在公网 | 改成 fail-closed：没有 auth 模块时只放行本机回环，远程一律 503 |
| 访客排队只按 Cookie 里的 gid 限 3 单 | 脚本每单前删一次 Cookie 换新 gid，把待批队列刷满，正常访客永远提交不了 | 追加**按 IP 限 3 单** + **同 IP 每小时最多 8 单** |
| `model` 参数未清洗 | `../../x.pth` 指到 weights 外面，torch.load 反序列化 = 远程代码执行面 | 一律 `basename` + 必须真实存在于 weights 目录 |
| `Content-Length` 无上限 | 声明 1GB 让面板把内存吃光 | 上限 256KB，超了回 413 并断开 |
| 无安全响应头 | 点击劫持、XSS 危害放大 | 加 CSP、`X-Frame-Options: DENY`、`nosniff`、`Referrer-Policy`、`Permissions-Policy` |
| 访客页把整首歌 JSON 拼进 `onclick` | 歌名里带 `&quot;` 就能注入 JS（存储型 XSS，可代站长点批准） | 只按下标引用，歌名一律 `esc()` |
| `/api/guest/models` 返回绝对路径 | 泄露服务器目录结构 | 访客接口剥掉 `dir` |
| 访客 Cookie 内容不限 | 塞 5KB 畸形串进数据库 / 页面 | 只认 16 位十六进制，否则重新发 |
| 无跨站校验、验证码图可无限刷、每次访问都写盘 | CSRF、CPU/磁盘放大 | 校验 Origin；同 IP 10 分钟限 40 张图；同一 IP 60 秒内不重复建访客记录 |
| HTTP/1.1 无连接超时 | 慢连接一直占线程 | 30 秒超时 |

另外：Cookie 增加 `HttpOnly`（访客 Cookie 也加），经 HTTPS 隧道时自动补 `Secure`；
审批**同时只跑 1 首**（GPU 一次一个，避免 3 单并发把显存打满）；审批前复查模型文件是否还在。

**注意**：这些都是常驻进程里的代码，改完必须重启面板（关黑窗口 → 重新双击 `E:\启动RVC.bat`）才生效。

## 成品复用：做过的不再重做（2026-11-02 第五轮）

**规则**：开跑前先查成品库，参数四样全同就直接把现成的交出去，一个字节都不重算。
- 翻唱指纹 = `歌曲 ID + 声线(.pth) + 升降调 + 是否清唱`（`cover.reuse_key`）
- 朗读指纹 = `文字全文 + 音色 + 底声 + 语速` 的 sha1 前 20 位（`tts.text_key`，索引里存哈希不存原文）
- 只有「索引里有记录、且 mp3 还在硬盘上（>1KB）」才算命中；文件被删过就重新生成。

**三处闸门**（`dashboard\cover.py` / `dashboard\tts.py` / `dashboard\guest.py`）
1. `cover.find_cached()` / `tts._find_cached()`：成品库首次命中 → 直接返回文件名，界面提示「复用已有成品」。
2. `cover._inflight`：同参数的活正在跑（另一个访客刚提交）→ 挂到同一个 job 上，不重复占 GPU，
   结果出来后两边都拿到同一首。任务结束（成功/失败）自动摘掉台账，失败的单下次还能重跑。
3. `tts.text_key` 写进 `index.json` 的 `tts_key` 字段；朗读同样内容直接秒回。

**界面上的体现**

## 审批队列：批准即排队，顺序可调（2026-11-02 第五轮）

**流程变了**：以前一次只能批一单（上一单没做完，批准直接报错）；现在
`等批准(pending) → 批准入队(queued) → 制作中(running) → 已完成(done)`。
批准多少单都行，它们安静排队，做完一单自动接力下一单（GPU 一次只跑一个，不变）。

- **默认先到先来**：按访客提交时间插位，先提交的排前面。
- **顺序随便调**：审批台新增「队列」标签页，每一单可以 ⤒置顶 / ↑上移 / ↓下移 / 移出，
  顶部显示「正在做：xxx · 排队 N 单」，还有「▶ 立即开始下一单」按钮。
- **命中成品库的单不排队**：批准时发现已经有现成成品，直接发给对方，不占队列也不占 GPU。
- **失败保护**：一单启动失败（比如后端 3333 没开）后自动暂停 60 秒再往下推，
  免得整队申请连着被打成 error；期间可以点「立即开始下一单」手动跳过冷却。
- **重启恢复**：面板重启后，看门狗线程会把队列里没做完的单接着做
  （以前重启会让 running 的单卡死，现在排队中的单也会自动恢复）。
- **访客看到的**：自己的申请显示「排队中 #2」（前面还有几单一目了然）；
  控制台首页待审批区右上角也会显示「队列 N 单 · 正在做 1 单 →」。

**新接口**（都要管理员）：`GET /api/admin/queue`、`POST /api/admin/move {id, dir: up/down/top/bottom}`、
`POST /api/admin/pump`。队列顺序存在 `guest_db.json` 的 `queue` 字段里（rid 列表）。

**回归**：新增 `dashboard\e2e_queue.py`（27 项全过：批准即入队、先到先来、置顶/下移、
做完自动接力、移出、命中不排队、落盘）。`e2e_reuse.py` 29/29、`e2e_security.py` 37/37 仍全过。
注意：测试脚本里设了 `RVC_NO_AUTOPUMP=1`，临时实例不会自动跑真任务；正式面板不要设这个变量。

## 被爆破的风险（2026-11-02 评估）

**公网侧基本无风险**：隧道只映射 8899，管理接口远程一律 403（没有密码这层可爆）；
访客页四道闸——验证码阶梯锁（连错 6/9/12 次锁 1/3/10 分钟）、取图限流（单 IP 40 张、
全局 150 张 / 10 分钟）、搜索总闸 50 次 / 10 分钟、申请配额（每 IP 3 单、全局待批 12），
最后还要你人工批准。就算全被攻破也只能塞垃圾单，不会自己烧显卡。

**但域名会被扫到**：`trycloudflare.com` 子域名会进证书透明度日志，扫描器能捞到。
实测访客库里已有一批云服务器 IP + 「未知设备·脚本」UA，访问 1~2 次就走，
全都停在访客页（搜索次数最高 6 次，没有一条是脚本刷的申请）。
不用的时候把关掉公网窗口，域名失效扫描就停了；下次重启换个新域名。

**局域网侧没有鉴权**：3333 / 7865 / 3002 都监听 0.0.0.0，同 WiFi 的设备能直连 3333
绕过审批直接跑 GPU、也能打开 7865 WebUI。手机插件要用 3333，所以没关。
- 在寝室 / 咖啡厅等公共 WiFi 用，同网设备就在这个风险里；
- 用手机 USB 共享网络时，只有手机能连，等于天然隔离（此时电脑 IP 一般是 `192.168.42.x`，
  插件里填的地址要跟着改，面板首页会显示当前 IP）。

**怎么查有没有人打**
- 管理接口被远程触碰会记到 `dashboard\security.log`（时间 / IP / 路径 / UA，超 512KB 自动截半）；
- 控制台「访客记录」里看：短时间大量 1 次访问 + 「未知设备·脚本」UA = 扫描器；
- 访客库里出现你没见过的申请（尤其同一 IP 连提多单）= 有人在试图刷队列。

## 2026-11-02（深夜）：第三轮细查漏洞（9 处）

**隐私（最重要的一处）**
- 「我的申请」以前按 IP 兜底找回 —— 手机 4G / 校园网一个出口 IP 后面是很多人，
  同网络的陌生人会直接看到你的申请（歌名、朗读原文）。已改成只认访客 id：
  Cookie 丢了就用浏览器 localStorage 里存的 id（`?gid=` 参数）找回，能看也能下载。
  换设备=重新开始（隐私换来的取舍）。回归里专门测了「同 IP 两人互不可见」。

**服务健壮性（防打挂）**
- 面板加了**并发连接上限 96**：以前一连接一线程、不设上限，公网开几百个慢连接
  （连上不发完请求，卡满 20 秒）就能把线程耗光，正经访客打不开。超出的直接 503。
- 访客计数（visits / searches）写盘加了**节流**：以前每个新访客都整份重写 100KB+
  JSON（还是在全局锁里），被刷时所有请求都卡在这。现在 2 秒内合并，巡队线程补写。
- 安全日志同 IP 5 秒只记一条（否则它自己变成写盘放大器）。
- 访客接口加**通用限流 120 次/分钟**（验证码/搜索各有更严的闸，这道兜扫描器）。

**纵深防御**
- 归档成品时，后端返回的文件路径**必须落在允许的临时目录里**（后端 temp / output /
  gradio temp / 系统临时目录）才复制+删除。3333 是独立进程还监听 0.0.0.0，
  万一它不是我们的后端，返回 C:/Windows/xxx.mp3 就会被复制进成品库并把原件删掉。
- 清理缓存的目录加了**形状校验**：盘根、C:/Windows、Program Files、用户主目录
  一律拒绝（GRADIO_TEMP_DIR 若被设成 C:/ 一次点击就清盘）。
- 「本机直连」判定补了 CF-Ray / CF-Visitor / X-Real-IP —— 万一哪天 CF-Connecting-IP
  被前置代理剥掉，只要还留着任一 Cloudflare 头就不会被当成站长。
- 验证码字符从 random 换成 secrets（random 的状态可从输出反推）；
  **没有 Pillow 时直接拒绝出图**，不再退回 SVG —— SVG 的答案是明文写在图片源码里的，
  那等于把验证码关掉。
- 翻唱/朗读共用一份 index.json，但两套读写代码各干各的，并发时可能互相覆盖丢记录。
  现在朗读直接走翻唱的加锁版本。
- 访客接口的异常详情只返回给本机（公网只看到「服务内部错误」），不再免费送内部路径。
- 搜歌失败提示不再回显内部异常（可能带内网地址）。

**3333 后端（下次重启 3333 生效，本轮没动运行中的进程）**
- `convert` 的 `split_model` 和 `song_name_src` 被直接拼进 `./output/<split>/<song>/`
  路径，是外部请求传的字符串 —— 传 `../../../Users/xxx/Desktop` 就能把分离结果写到
  盘上任意位置。现在入口统一归一化成安全字符。

**回归**
- 新增 `e2e_privacy.py` 39 项（IP 串号 / gid 找回 / 下载权限 / 路径白名单 / 并发上限 /
  日志节流 / 验证码不降级 / 写盘节流 / 接口限流 / 清理路径闸）。
- `e2e_security` 43 / `e2e_reuse` 29 / `e2e_queue` 27 全部不变。总计 138 项全绿。
